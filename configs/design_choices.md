| **0. Frame**                       | Build an auditable, searchable knowledge base from a scanned Bengali crop-disease book. The A2 target is evidence-grounded retrieval; final agent answers remain an A3 concern.                       | The source corpus has 403 scans and approximately 116,539 words. The KB deliberately includes only 378 chapter pages; 25 front/back matter or auxiliary scans are excluded. Chapter-level splitting gives 264 training, 57 validation, and 57 test pages. Test pages are held out from tuning and indexing. | The configuration file is the authoritative record for processing, vision, embedding, and index choices.                                             | Use chapter-aware filtering and splitting so near-duplicate pages from the same chapter cannot leak between splits. Store page identity and provenance with every downstream artifact.                                                                                                                                                                        | The pipeline uses**Page → Region → Chunk** concepts. A page remains the unit of source provenance; layout regions provide structural metadata; chunks are the retrieval units.                                                              | EDA was performed locally and in Kaggle notebooks to inspect page dimensions, skew, gutters, columns, and likely non-text regions before fixing the pipeline.                                                                                                                                                                                                                                                                                                                                                                                                                                         | The workflow is batch-oriented and can run locally or in Kaggle.`device: auto` selects CUDA when available and otherwise uses CPU-compatible paths.                                                                              | Corpus snapshots use deterministic SHA-256 hashes. Configuration, page IDs, split membership, and source provenance are intended to be retained with derived artifacts for auditability.                           |
| **1. Ingest + enhance**            | Book scans have a neighbouring-page gutter, mild rotation, yellow paper, uneven illumination, and blurred outer edges. Over-processing can damage Bengali glyphs, so correction must be conservative. | Input consists of the original scanned page images under`data/raw/krishipath`. Raw files are read-only inputs; derived images are written under `data/interim/preprocessed`.                                                                                                                            | Pillow handles image loading and EXIF orientation; OpenCV supplies line detection for deskewing. The optional learned enhancement stage is disabled. | Apply EXIF transpose; trim the left gutter by 80 px to prevent OCR from reading the facing page; optionally trim a uniform border (currently 0); estimate a consensus skew from Hough line angles; rotate only when its magnitude is between 0.15° and 2.0°. No denoising, whitening, sharpening, or binarization is applied in the selected configuration. | Preprocessing produces a derived image for the same`Page` rather than changing its ID or raw source. The pipeline can run with preprocessing disabled for comparison.                                                                             | Earlier experiments with more aggressive cropping, adaptive binarization, background normalization, and denoising made some pages look worse or increased OCR error. The final A2 setting therefore uses subtle trimming and bounded deskewing only.                                                                                                                                                                                                                                                                                                                                                  | Pillow/OpenCV preprocessing is CPU-safe; CUDA is not required. Output location is configurable so local and Kaggle runs do not overwrite raw data.                                                                                 | Record preprocessing parameters in`configs/config.yaml`; preserve raw images; tie derived outputs to the source page ID and corpus snapshot. Enhancement is explicitly `enabled: false`, not silently assumed. |
| **2. Layout**                      | Preserve structural evidence and reading order for headings, paragraphs, lists, figures, and tables without losing text through unreliable tight cropping.                                            | Layout consumes each preprocessed page and returns labelled boxes with coordinates, confidence, and page ID. It does not alter the OCR source image.                                                                                                                                                        | `juliozhao/DocLayout-YOLO-DocStructBench`, a DocLayout-YOLO / YOLOv10 checkpoint, is used for document-structure detection.                        | Run at image size 1024 with confidence threshold 0.20. Map model labels to repository region kinds and sort detections in top-to-bottom reading order. The checkpoint may be downloaded from Hugging Face on first use and cached afterwards.                                                                                                                 | `Region` objects carry a bounding box and semantic kind, attached to their parent Page. OCR remains full-page rather than box-only because experiments showed cropped regions could omit Bengali characters, continuation text, or table content. | PaddleOCR layout was investigated but failed in Kaggle due to incompatible Torch/NCCL libraries. Docling/VLM outputs were fragmented or missed content on this corpus. Visual overlays showed DocLayout-YOLO gives the most useful structural metadata, even where its labels are imperfect.                                                                                                                                                                                                                                                                                                          | The implementation resolves`auto` to CUDA when available and CPU otherwise. CPU execution is supported but slower; the model cache or first-run Internet access must be available.                                               | Save region coordinates, confidence, model identifier, and layout settings with processing outputs. Use page overlays during development to make layout decisions inspectable.                                     |
| **3. OCR**                         | Accurately transcribe printed Bengali, Bengali conjuncts, numerals, punctuation, and embedded English/Latin scientific terms from imperfect scans.                                                    | OCR processes the 378 selected chapter pages. The 57 held-out test pages and`grading_kit/labels.jsonl` are evaluation-only: they are never used for OCR tuning or index construction.                                                                                                                     | EasyOCR with pretrained Bengali and English recognition models is the selected baseline:`languages: [bn, en]`.                                     | Run recognition once on the full processed page with`min_confidence: 0.0`, then normalize output using Unicode NFC and whitespace cleanup. Emit one provenance-preserving page chunk per OCR page in the current baseline.                                                                                                                                  | Layout is retained as metadata, while the full page is transcribed to avoid omission caused by independently cropped boxes. Each OCR chunk retains source page ID, document ID, and provenance.                                                     | Tesseract and EasyOCR were tried for Bengali. Surya OCR performed well on a teammate’s RTX 5060 Ti but was difficult to reproduce in Kaggle because of vLLM/GPU dependency constraints. PaddleOCR could not import in the tested Kaggle environment. EasyOCR was chosen for reproducible GPU/CPU execution. Exploratory 57-page measurements after careful normalization were: full-page EasyOCR CER 0.3210, WER 0.4529, character F1 0.7794; layout-cropped OCR was worse (CER 0.4411, WER 0.5957, F1 0.7237). These are preliminary and must be reproduced after manual review of held-out labels. | `device: auto` enables a CUDA reader when possible and a CPU reader otherwise. Model weights are downloaded/cached on first use. CPU mode is slower but remains functional for autograder-compatible execution.                  | Persist OCR text with source-page metadata and effective model/configuration. Report normalized CER, WER, and character F1 on held-out labels; never mix those labels into the indexed corpus.                     |

Chunk metadata stores stable chunk ID, page/document ID, source text, and offsets.                                                                                                            | `BAAI/bge-m3` is the configured multilingual embedding model (1024 dimensions), with FAISS HNSW as the vector index.                               | Normalize text before chunking; use the BGE tokenizer to create 256-token chunks with 32-token overlap; L2-normalize embeddings; build HNSW with`M=32`, `efConstruction=80`, and query `efSearch=64`. Optional remedy aliases are configuration-driven and presently empty.                                                                             | The persisted index has a FAISS binary plus JSONL chunk metadata so an embedding hit can always be explained through its original OCR text and page ID.                                                                                             | A teammate-provided prototype index (2,422 vectors, 384 dimensions) was inspected and could self-retrieve, but it does not match the configured BGE-M3 1024-dimensional setup and lacks sufficient encoder provenance. ## Active configuration summary

The values implemented in `configs/config.yaml` are: chapter-only ingest; preprocessing enabled with an 80 px left trim and bounded deskewing; enhancement disabled; DocLayout-YOLO layout detection; EasyOCR with Bengali and English language support; BGE-M3 embeddings; and a FAISS HNSW index. Any future experiment must change the configuration and be reported with its corpus and index version so results remain comparable.

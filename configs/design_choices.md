# Per-stage design choices (A2 deliverable)

This document covers the A2 knowledge-base build: framing plus Stages 1–4.
It deliberately excludes retrieval, agent, RL, and serving decisions, which
belong to later milestones.

* [ ] StageProblem statementDataModelMethodsDesignDevelopmentDeploymentMLOps**0. Frame**Build a searchable, auditable evidence base from a scanned Bengali crop-disease textbook. A2 produces retrieval-ready evidence, not generated answers.403 source scans and about 116,539 words. The KB scope is 378 chapter pages; 25 auxiliary scans are excluded. Chapter-grouped splits are 264 train, 57 validation, and 57 test pages.Configuration is the source of truth for all selected A2 models and parameters.Chapter ranges and split lists prevent chapters appearing in more than one split. Held-out test labels are excluded from indexing and tuning.`Page` identifies a source scan, `Region` holds layout metadata, and `Chunk` is the retrieval unit. Page IDs are retained through all stages.EDA inspected dimensions, gutters, columns, skew, and scan-quality variation before the settings were chosen.Batch build, with a CPU-safe committed configuration. The standalone Kaggle OCR runner can explicitly use a supported GPU.`snapshot()` deterministically hashes a corpus; `validate()` checks pages and chapter splits. Both utilities exist but are not yet called inside `build_knowledge_base()`.**1. Ingest + preprocess**Reduce adjacent-page leakage and mild skew without damaging Bengali diacritics, conjuncts, or faint strokes.Raw images under`data/raw/krishipath` are immutable inputs. Derived images are written under `data/interim/preprocessed`.Pillow handles image/EXIF orientation; OpenCV provides Hough-line skew estimation. No learned enhancement model is selected.EXIF transpose; 80 px left trim; 0 px uniform border trim; rotate only for a consensus skew between 0.15° and 2.0°. Denoising, whitening, sharpening, and binarization are disabled.The processed file replaces only`Page.image_path` in the in-memory record; raw IDs and raw images remain unchanged.Stronger crops, adaptive binarization, background normalization, and denoising were tried and made some pages look worse or increased OCR error.Pillow/OpenCV run on CPU. This is the committed reproducible baseline.Parameters are recorded in`config.yaml`; raw images and their derived counterparts remain separately identifiable.**2. Layout**Capture headings, paragraphs, lists, tables, figures, and approximate reading order as structural evidence without treating imperfect boxes as OCR boundaries.Each processed page yields labelled coordinates and a page ID. Layout does not alter OCR text or the source image.**Selected:** `juliozhao/DocLayout-YOLO-DocStructBench` through DocLayout-YOLO / YOLOv10. **Compared:** Docling, Qwen3-VL, Surya Layout, and DocLayout-YOLO.Use`imgsz=1024`, `score_thr=0.20`, and top-to-bottom sorting. Labels map to `heading`, `table`, `figure`, or `text`. Public weights are cached after first download.Boxes become`Region` metadata and a page metadata map. OCR reads the full processed page once because region-cropped OCR omitted boundary characters and content.Representative Bengali-page overlays were compared for coverage, grouping, and reading-order usefulness. DocLayout-YOLO produced the most coherent practical output.The committed baseline uses CPU because the teammate's detected`sm_120` GPU is not supported reliably by its installed Torch build. A compatible Kaggle GPU can be selected explicitly for experiments.Region kind, box coordinates, model identifier, and threshold can be retained with run outputs; overlays provide inspectable evidence.**3. OCR**Transcribe printed Bangla conjuncts, vowel marks, numerals, punctuation, and embedded English/Latin crop-pathology terms.OCR uses only the 378 chapter pages. The 57 held-out labelled pages are evaluation-only and are not used for training, preprocessing selection, or index input.**Selected:** pretrained EasyOCR with `languages: [bn, en]`. **Compared:** Tesseract, Surya OCR, and EasyOCR.Full-page recognition at`min_confidence=0.0`; sort lines by top/left coordinates; normalize Unicode to NFC and collapse whitespace; emit one source OCR chunk per page before tokenizer splitting.Layout remains provenance metadata, not a hard OCR crop. Each source chunk retains document and page identity.Surya OCR worked well locally on a teammate's RTX 4060 Ti. EasyOCR was selected because it handles the Bengali/English mix and can run directly on CPU, unlike the less reproducible Surya deployment path. Exploratory full-page EasyOCR results over 57 held-out pages were CER 0.3210, WER 0.4529, and character F1 0.7794; box-cropped OCR was worse (0.4411, 0.5957, 0.7237). These require rerunning after manual label review before final reporting.Committed configuration uses CPU for a reliable autograder baseline. A compatible GPU may be specified in a Kaggle-only run;`auto` is not used because CUDA availability alone does not prove runtime compatibility.Persist OCR text with page/document metadata, model/language settings, and normalized held-out CER/WER/F1 measurements.**4. Index**Retrieve Bengali crop-disease evidence efficiently while preserving a trace from a result to its OCR text and source page.Index OCR output from the 378 in-scope pages only. Held-out reference labels are excluded.`BAAI/bge-m3` at 1024 dimensions, with FAISS `IndexHNSWFlat`.NFC-clean text is paragraph-grouped and BGE-tokenized into 256-token chunks with 32-token overlap. Vectors are L2-normalized; HNSW uses inner-product similarity with`M=32`, `efConstruction=40`, and `efSearch=64`.Persist`index.faiss`, `chunks.jsonl`, and `metadata.json`. Chunk records include IDs, document IDs, page IDs, and text.A teammate-provided 384-dimensional prototype index could self-retrieve but is not accepted as final evidence: it does not match BGE-M3's configured dimension, model provenance, or chapter-only scope.BGE-M3 can run on CPU for correctness but is slower; a compatible Kaggle GPU is recommended for the one-off full-corpus build.Index metadata records vector count, dimension, metric, and HNSW settings. The final build should additionally record the corpus hash and effective configuration.

## Active configuration summary

The committed configuration uses CPU for the selected layout, OCR, and
embedding stages. This avoids a false GPU selection on an unsupported `sm_120`
Torch installation. For Kaggle only, use an explicit compatible GPU override in
the standalone batch runner rather than changing the committed baseline.

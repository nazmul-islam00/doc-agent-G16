# Per-stage design choices (A2 deliverable)

| Stage | Problem statement | Data | Model | Methods | Design | Development | Deployment | MLOps |
|---|---|---|---|---|---|---|---|---|
| 0 Frame | Answer crop-disease questions from cited scanned evidence. | 403-page Bangla *Shashyer Rog* scan; 378 chapter pages form the KB. | No learned model. | Chapter-grouped train/validation/test split; 57 held-out labelled test pages. | Stable page IDs preserve provenance from image to chunk. | YAML configuration and typed Pydantic contracts. | Batch KB build on local/WSL machine. | Provenance records source, licence, counts, and split policy. |
| 1 Ingest + enhance | Convert raw scans into consistently readable derived page images. | JPEG scans, including skew, shadows, uneven contrast, Bangla conjuncts, and Latin terms. | Classical OpenCV/Pillow processing; learned enhancement disabled for baseline. | EXIF correction, bounded deskew, page crop, border trim, denoise, background normalisation; raw images are immutable. | `Page` retains ID and document ID while its derived image path changes. | Inspect a representative sample and retain raw-to-derived mapping. | Derived PNGs go to `data/interim/preprocessed/`; CPU-compatible. | Rebuildable from `scripts/get_data.sh`; preprocessing parameters live in config. |
| 2 Layout | Separate meaningful page regions and preserve a usable reading order before OCR. | Preprocessed full pages with headings, prose, figures, tables, lists, and occasional multi-column layouts. | Pretrained Surya layout predictor. | Detect regions; map labels to text/heading/table/figure; sort blocks by column and vertical position. | `Region(page_id, bbox, kind)` links each region to its source page. | Visually inspect detected regions on difficult and table-containing pages. | Batched local inference; no network needed after model download. | Record Surya checkpoint/version and retain page IDs for error analysis. |
| 3 OCR | Produce searchable Bangla text while retaining mixed English/Latin terminology. | Layout-informed, preprocessed Bangla pages; 57 held-out manual transcripts are evaluation-only. | Pretrained Surya multilingual recognition model. | Full-page contextual recognition, HTML-to-text conversion, and column-aware block ordering; no fine-tuning claimed at A2 baseline. | Each `Chunk` keeps document and source page IDs for later citations. | Notebook reports held-out character F1 and shows per-page errors. | CPU fallback; CUDA may be selected through config when available. | Never use held-out labels for model selection; save OCR quality and failures in the notebook/form. |
| 4 Index | Turn OCR output into searchable, citation-preserving vectors. | Normalised OCR chunks with Bangla and Latin technical terms. | `sentence-transformers/all-MiniLM-L6-v2` (384-D) plus FAISS HNSW. | Unicode NFC and whitespace cleanup; 256-token windows with 32-token overlap; L2-normalised vectors and inner-product HNSW. | `Chunk` metadata is persisted beside the FAISS index, retaining page provenance. | Check chunk/vector count equality and reload index metadata; notebook demonstrates one query. | One-pass `scripts/build_index.sh` creates `data/index/` artifacts. | Metadata stores type, dimension, count, and HNSW settings; rebuild from config and source scans. |
| 5 Retrieval | Planned for A3: return top-k evidence chunks for a question. | Persisted chunk vectors and metadata. | Dense FAISS search; reranker evaluated in A3. | Top-k score threshold and widening policy. | Retrieve returns scored `Chunk` objects. | Recall@k against authored tasks. | Loaded index in query service. | Log query, scores, and retrieved chunk IDs. |
| 6 Agent | Planned for A3: answer only from retrieved evidence with citations. | Query plus retrieved chunks/pages. | Configured LLM wrapper. | Evidence-gated re-search, abstention, tools, and guardrails. | Fixed perceive-decide-act loop and citation contract. | Unit and cross-cutting tests. | API/UI in A4. | Replayable trace per agent run. |
| 7 RL/RLVR | Optional A3 bonus: learn tool/retrieval actions and verifiable extraction. | Authored fact tasks and trajectories. | PPO policy; exact-match reward. | Gym environment and RLVR. | Policy selects fixed tool interface actions. | Compare against rule baseline. | Offline training only. | Log reward and checkpoint metadata. |
| 8 Serving | Planned for A4: expose cited answers safely. | Indexed KB and validated configurations. | FastAPI and Gradio. | Batching and health checks. | API calls the fixed pipeline interface. | Smoke tests and Docker build. | Docker/HF Spaces target. | Monitor latency and failures. |
| 9 Eval | Planned for A3/A4: measure quality, safety, and the auditable NFR. | Held-out transcripts, authored tasks, and traces. | Metrics and optional judge. | OCR F1, recall@k, groundedness, citation accuracy, ablation. | Evaluation reads the same contracts/artifacts as production. | Seeded reproducible runs. | Generate reports from saved artifacts. | Audit completeness target: at least 95% replayable traces and citations on all returned answers. |
